# Marketplace Auto Relay

Половина системы уведомлений Marketplace Auto, вынесенная за пределы РФ.
Единственный сервис, которому разрешено обращаться к API мессенджера.

## Зачем он есть

С основного сервера `api.telegram.org` недоступен: TCP-соединение не
устанавливается ни по IPv4, ни по IPv6, хотя Wildberries и остальной интернет с
той же машины доступны. Завернуть весь трафик через заграницу нельзя — запросы к
WB обязаны уходить с российского адреса. Поэтому наружу ходит один сервис, и
только он.

## Что он даёт основному серверу

Основной сервер не знает ни токенов ботов, ни адреса Telegram, ни формата его
апдейтов: он общается с релеем в терминах `bot_code`, `recipient` и текста.
Смена мессенджера — это правки в `relay/telegram.py`, а не сквозная переделка.

## Что он делает

- **Хранит токены ботов** — зашифрованными, и только у себя.
- **Отправляет сообщения** по запросу основного сервера, с защитой от повторной
  доставки: повтор после потерянного ответа не дойдёт до селлера вторым сообщением.
- **Принимает входящие** от подписчиков, приводит к единому виду и копит, пока
  основной сервер за ними не придёт.

## Контракт

| Метод | Назначение |
| --- | --- |
| `POST /api/v1/bots` | регистрация, обновление и удаление бота |
| `POST /api/v1/messages/send` | отправка сообщения |
| `GET /api/v1/updates` | забрать апдейты после курсора (long polling) |
| `GET /ready` | состояние поллеров по каждому боту |
| `GET /health` | живость процесса, без обращений к мессенджеру |

Всё, кроме `/health`, требует JWT в заголовке `Authorization`. Секрет подписи
общий с основным сервером, аудитории для двух направлений разные.

Коды ответа `/messages/send`: `200` доставлено, `404` бот неизвестен, `409`
токен занят другим ботом, `422` мессенджер отказал осмысленно (чат не найден,
бот заблокирован) — повтор бессмысленен, `429` с `Retry-After`, `502` мессенджер
недоступен — повторить позже.
